## Arquitetura do binding AIDL (oficial)

O contrato REAL de `com.csjbot.sdkhandler` (difere dos scaffolds antigos):

```aidl
// O que o RobotSdkService devolve no onBind() (MyBinder extends IAarToSdkApp.Stub):
interface IAarToSdkApp {
    void aarMsgToSDKApp(String msg);   // app cliente ENVIA comandos JSON ao SDK
    void connectToSDK(String appName); // handshake inicial do cliente
}

// O que o app CLIENTE deve expor num Service próprio (o SDK binda DE VOLTA
// usando a ação "com.csjbot.sdk.connect"):
interface ISdkAppToAar {
    void connectToSDKSucceed();        // SDK confirma o handshake
    void sdkAppMsgToAar(String msg);   // SDK ENTREGA eventos/respostas JSON
}
```

Fluxo completo:
1. Cliente binda em `com.csjbot.robotsdk.ten` / `com.csjbot.robotsdk.service.RobotSdkService`
   (ação `com.csjbot.robotsdkservice.startservice`) e recebe `IAarToSdkApp`.
2. Cliente chama `connectToSDK(<nome do app>)`.
3. O SDK binda de volta no Service do cliente que declara a ação
   `com.csjbot.sdk.connect` e recebe `ISdkAppToAar`; chama `connectToSDKSucceed()`.
4. Comandos: cliente → `aarMsgToSDKApp(json)`; eventos: SDK → `sdkAppMsgToAar(json)`.

As mensagens JSON usam os nomes de comando abaixo (campo de comando + `data`),
padrão `coshandler`.
